## 1. Overall Assessment: How Far Does a Lisp / S-form + Unison-Inspired Architecture Go?

Kotoba is the language at the heart of a modern Lisp machine in development, integrating **Lisp / S-form homoiconicity (code as data with bounded desugaring)**, **closed static types and algebraic data types**, **capability / effect-row authority boundaries**, and **Unison-inspired content-addressed definitions (`DefCID`) with abilities** into a single compilation pipeline. As a result, it addresses **safety, reproducibility, and authority confinement** deeply, while leaving clear gaps in **TypeScript-style flexible polymorphism, resident IDE/LSP experience, and full parity between the reference semantics and the self-hosted compiler**.

### 1.1 Strongly Addressed Areas (Design + Implementation Present)

**1. Making invalid states unrepresentable**

- Absence is represented as `[:option T]` rather than sentinel values (`-1` or implicit `null`), and implicit numeric truthiness as well as implicit numeric conversions (`i64` ↔ `f64` ↔ `f32`) are rejected as type errors.
- Failure is represented explicitly as `[:result T E]`; `throw`/`try`/`catch` also elaborate at compile time into `[:result T E]` recorded in function boundary types and the `:abort` effect row (uncaught `:abort` at an `export` boundary is rejected).
- `[:variant id cases]`, nominal `defrecord` (up to 32 fields), and exhaustive `option-match` / `result-match-of` / `variant-match` close the state space with algebraic data types (ADTs).
- `nil` fields inside keyword-map literals are resolved to `[:option T]` from contextual and intra-module usage types (`absence-resolution` / `ck-kopt-scan`).

**2. Confining side effects and authority leakage (capability-safe execution)**

- Fixed-point analysis over a closed call graph infers each function's effect row and intersects it with `:capabilities` declarations, `{:effects #{...}}` ceilings, and execution policy (deny-by-default).
- At runtime, an operation executes only if it passes the 5-layer intersection: **compiler evidence ∩ requested operation ∩ delegation scope ∩ local policy ∩ current provider state** ([`logic-authority.md`](./logic-authority.md)).
- Capability values undergo affine consumption checks (`affine.cljk` in `kotoba-sema`), preventing unrestricted authority duplication and ambient authority minting from `def` or EDN literals.

**3. Unison-inspired content-addressed code identity**

- `DefCID` (payload-v2) hashes **checked Typed KIR + interface (IF) + effect row + dependency DefCIDs** via DAG-CBOR / SHA-256 rather than source text or Git commits ([`ADR-kotoba-code-identity-and-abilities.md`](../adr/ADR-kotoba-code-identity-and-abilities.md)).
- It is invariant under α-renaming (local variable renames), and monomorphized clones from record row polymorphism depend only on concrete types and bodies, enabling identical `DefCID` and compilation-cache sharing across modules and hand-written equivalents (`ADR 0353`).

**4. Homoiconicity, determinism, and bounded computation**

- Reader syntax is restricted to a closed EDN / S-form subset with left-to-right call-by-value evaluation ([`semantics-ssot.md`](./semantics-ssot.md)).
- Syntactic extension forbids arbitrary guest macros and permits only pure, non-capturing, depth/node-bounded `defdesugar`, keeping expanded forms statically checkable ([`surface-matrix.md`](./surface-matrix.md)).
- Per-backend fuel accounting makes resource boundaries explicit while keeping profile rules separate in [`fuel-model.md`](./fuel-model.md) (§2) and [`lang/limits.edn`](../../lang/limits.edn): KIR, Wasm (`wasm32-kotoba-v1`), and JS (`js-kotoba-v1`) charge 1 unit per function entry (default 512), whereas POSIX native `kexe` (AArch64 / x86-64) leaves deterministic fuel off by default and charges function entries plus 1 unit per constructor allocation only when metered opt-in (`KEXE_FUEL=n` / `--fuel n`, measured 2026-10-09 under `ADR 0353` `:allocation-budget-native`).

### 1.2 Partial Coverage and Remaining Gaps (Especially TypeScript-Style Types, Unions, and LSP)

**1. TypeScript-style type expressiveness and inference (no Algorithm W)**

- **No general type variables or Hindley–Milner Algorithm W**: `:element-type-polymorphism` in [`lang/surface-status.edn`](../../lang/surface-status.edn) is `:not-yet-implemented`.
- Instead, Kotoba uses **rejection-driven iterative fixed-point refinement (`infer-absent-parameter-types` / `KW-PINFER`)**, **record-only row polymorphism with compile-time monomorphization (`{:k T | r}`)**, and **module type-parameter substitution (`:params` / `:with`)** in the hosted linker.
- **Union types and narrowing**: Tagged sums (`[:variant ...]`, `[:option T]`, `[:result T E]`) are implemented, and control-flow narrowing with predicates such as `string?` / `vector?` works over the Hiccup ADT in `kotoba-sema`. However, TypeScript-style **arbitrary untagged unions `A | B`**, **general control-flow narrowing over arbitrary types**, and **gradual typing with `any`/`unknown`** do not exist (only tagged closed sum types are admitted by design for safety).

**2. LSP and IDE developer experience**

- `kotoba.lsp` (diagnostic, position, and range data layer) and `kotoba.lsp.rpc` (JSON-RPC 2.0 framing) exist as M6 horizontal foundational libraries ([`ADR-kotoba-lang-foundational-stdlib.md`](../adr/ADR-kotoba-lang-foundational-stdlib.md)).
- However, a **resident, incremental, demand-driven LSP server (Salsa-style query engine)** comparable to TypeScript (`tsserver`) or Rust (`rust-analyzer`) — providing live completion, hover type display, go-to-definition, and type-directed refactoring — is not yet built.

**3. Specification (`kotoba-sema`) vs. self-hosted compiler (`amu/seed`) implementation gap**

- As measured on 2026-11-07, out of 86 positive conformance fixtures, the self-hosted compiler accepts 48/86 on `aarch64-macos` and 29/86 each on `wasm32-browser` / `js-browser` (all 26/26 negative fixtures are rejected across every target).
- Module type parameters (`E6023`), cross-module interfaces carrying record/keyword/function types (`E6017`), `defdesugar`, multi-source `map`, `lazy-*`, and `extend-protocol default` are not yet reached on the self-hosted path.

**4. Unison-style ecosystem exchange and formal verification**

- Local exchange specifications exist for `definition-patch` / `share` ([`ADR-kotoba-definition-patch-share.md`](../adr/ADR-kotoba-definition-patch-share.md)), but networked synchronization, concurrent patch merging, and self-hosted `(ref "bafy...")` CID resolution remain unimplemented.
- Semantics-preservation proofs for compiler transformations in Lean 4 are at their initial slice: `KOTOBA-963` (SIR `i64` constant-addition folding T2 in `kotoba-lang/amu` branch `com-junkawasaki/kotoba-963-sir-lean`, `96898e7a`).

### 1.3 Intentionally Excluded Areas (Design Constraints, Not Defects)

- **Total termination proofs**: Consistent with Rice's theorem ([`computability-and-safety.md`](./computability-and-safety.md)), Kotoba does not require general termination proofs for arbitrary admitted programs; bounded execution relies on finite resource budgets, fuel, and host interruption.
- **Rust-style general borrow checker**: Kotoba does not enforce lifetimes or borrowing across arbitrary values; affine checking is scoped to capability handles and operations like `vector-assoc!`, while ordinary values rely on immutable persistent data structures.
- **Ambient dynamic execution**: Runtime string `eval`, dynamic code loading, ambient `require`, arbitrary JVM/JS FFI, and shared-memory multithreading/STM are permanently excluded as `intentional-security-constraint` invariants.

## 4. Open Gaps and Priority Roadmap

Ordering the remaining technical gaps from daily development and current contracts by priority for developer experience and language convergence yields five items:

1. **Resident incremental LSP server**: Wire the existing `kotoba.lsp` / `kotoba.lsp.rpc` libraries directly into the `kotoba-sema` / `amu` type checker and `DefCID` index to deliver completion, hover type display, go-to-definition, and refactoring in IDEs.
2. **Convergence of `kotoba-sema` and `amu/seed` self-hosted compiler (48/86 → 86/86)**: Systematically close unreached features — `extend-protocol default`, cross-module interfaces (`E6017`), `defdesugar`, multi-source `map`, `lazy-*`, etc. — tracked by an authoritative spec-delta table and automated differential tests.
3. **Policy decision on general polymorphism (`:element-type-polymorphism`)**: Decide whether to bring module `:params` (`E6023`) into the self-hosted compiler or introduce constrained generics / bounded type variables compatible with determinism and `DefCID` (without adopting full Algorithm W).
4. **Completing the Unison-style exchange fabric**: Implement networked transport, signature verification, and concurrent merging for `definition-patch` / `share`, alongside self-hosted `(ref "bafy...")` direct references (remaining work from `ADR 0411`).
5. **Expanding 99% target coverage and Lean 4 formal proofs**: Gather L1 real-device evidence for Android, Windows, and iOS (`ADR 0410`) and extend semantics-preservation proofs from `KOTOBA-963` (constant-addition folding) into `KOTOBA-964`/`965` across KIR → SIR → machine code.
